# Preserve diagnostic reservations across restart in a private SQLite ledger

Operator recovery follow-up: [ADR 0004](0004-offline-operator-attested-release.md) adds offline attested release and schema-2 audit; the persistence guarantees below remain in force.

In-memory fail-closed reservations are insufficient when an MCP process restarts while EOS work may still run or start later. Production diagnostic execution therefore uses Node's built-in SQLite on private persistent local storage: commit a reservation before dispatch, commit confirmed removal before capacity reuse, and restore unfinished records as uncertain. A separate SQLite ownership database holds an exclusive OS-managed lock for the server lifetime, so process crashes release ownership without guessing from PID or lock age. Prefer one active server per ledger over independent processes silently allocating fresh capacity. Existing state is validated and bound to the canonical inventory identity; corruption, missing companion files, incompatible schemas, and write failures block work rather than recreate empty capacity.

The default path is inventory-keyed beneath the user's XDG state directory; `diagnostics.stateFile` permits an explicit stable location. State files must stay together on a filesystem honoring SQLite locking/sync. Changing inventory identity, relocating/deleting all state, ephemeral volumes, and old in-memory executions are not automatic migrations or recovery mechanisms. Credentials, destinations, and EOS output are not journaled. `inspect-diagnostics` provides offline read-only inspection without device calls or ownership takeover, but no reset/release command is introduced.

This extends the persistence limitation in ADR 0002, not its requirement for positive completion evidence. Installed EOS exposes an execution-stage requestTimeout, but no dispatch-relative/process-exit bound or durable status token was qualified; see [the investigation](../research/eos-diagnostic-lifecycle.md). Post-dispatch RPC interruption errors remain uncertain. Native timer enablement, operator attestation, and out-of-band fencing/reconciliation require explicit qualification rather than inferring completion from silence.
